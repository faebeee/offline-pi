Self-hosted · offline · Raspberry Pi

When the network goes down, the outpost stays up.

outpost turns a Raspberry Pi into a small offline base: maps, an emergency library, shared files, a notice board and a supplies list, for everyone on its Wi-Fi. Set it up once while you have internet; after that it needs none.

Install See the modules
  • Offline no cloud, no CDN, no accounts elsewhere
  • One address every screen at http://<pi>:8080
  • Starts at boot back by itself after a power cut
01 · Purpose

Useful information and a place to coordinate, without internet

A storm, a long power cut, a cabin or a boat without coverage: the phone network and the internet are gone, but the people around you still need to find their way, look up first aid, share photos of the damage and know who needs what. outpost keeps all of that on a Raspberry Pi. Phones and laptops join the Pi's own Wi-Fi hotspot (or your home network) and open one web page. Nothing to install on them.

Works offline

Maps, books and everything people share live on the Pi. Fonts, icons and the app itself too: no request ever leaves it.

Its own Wi-Fi

With the hotspot fallback, the Pi opens its own Wi-Fi when its usual one is out of range, so anyone nearby can join. One port, one web app for every module.

Yours

Open source and self-hosted. Accounts for everyone who uses it; admins keep control of the box.

02 · Modules

What is on the box

Pick the modules you want when you install; Files, Board and Supplies are always there. Everything is one web app: the modules are screens in the same menu.

For everyone

  • Module
    Maps

    Download regions once, then pan, zoom and search places offline. Save your own places: meeting points, water, shelter.

  • Module
    Library

    Wikipedia, medical guides and survival manuals (Kiwix), with full-text search and an "In an emergency" index: CPR, bleeding, hypothermia, water purification.

  • Built in
    Files

    A shared folder for everyone on the Wi-Fi: photos, scans of documents, manuals. Upload with drag and drop, open and download anywhere.

  • Built in
    Board

    A notice board: news for everyone, what people need, what they can offer, and check-ins ("safe, at the school").

  • Built in
    Supplies

    Your emergency stock: what, how much, where and until when. Warns before things expire and tells you how many days the water lasts.

  • Module
    Network

    Who is on the Pi's hotspot: device, vendor, signal. Admins block devices that misbehave.

For admins

  • System

    Temperature, power, storage, network and the modules, live.

  • Diagnostics

    What works and what doesn't, with a fix for each problem.

  • Logs

    Every module's log lines, live and filterable.

  • Settings

    Every setting and data folder, with its size.

  • Users

    The accounts, and who is an admin.

  • Info

    The whole documentation, readable offline (for everyone).

03 · How it works

One app, a few containers, one port

phone / laptop ──Wi-Fi──▶ Raspberry Pi :8080
                           └─ core: the web app, the API, logins
                                ├─ maps       offline map tiles and places
                                ├─ library    Kiwix books
                                └─ network    devices on the hotspot
                           data: one folder, e.g. on an SSD
  • Podman, rootless. Each module is a container; core starts and stops them. No Docker, no root.
  • Ready-made images. Installing and updating download images built for 64-bit Pis and PCs, in minutes instead of a long build on the Pi.
  • Your data in one folder. Put it on an SSD for maps and books; re-run the installer to move it.
  • Starts at boot and stops cleanly at shutdown, so a power cut doesn't leave it off.
04 · Install

One command on the Pi

On a Raspberry Pi with 64-bit Raspberry Pi OS (or any Linux machine), as your normal user, with internet:

curl -fsSL https://raw.githubusercontent.com/faebeee/offline-pi/main/get.sh | bash

Prefer to look first? git clone https://github.com/faebeee/offline-pi.git ~/outpost && cd ~/outpost && ./install.sh does the same.

What it does

  1. Checks the system. Installs git if it is missing, downloads outpost to ~/outpost and offers to install Podman and the compose tool.
  2. Asks only what it must. Which modules you want, where the data goes (one folder, for example on an SSD) and, with Network, whether the Wi-Fi hotspot should be on and on which interface.
  3. Downloads and starts. The ready-made images for this version, then outpost itself, and makes it start at every boot.
  4. Prints a setup code. Open http://<pi>:8080, enter the code and create the admin account. Only someone with access to the Pi can, so nobody else on the network can claim it first.

Want to choose the port, who may connect, or a folder per module? Run ./install.sh --advanced.

You need

  • A Raspberry Pi 5 (others work too) with the official power supply
  • An SSD for maps and books (recommended; give it enough power)
  • Internet during the install and to download maps and books
  • A little comfort with a terminal for the setup; day to day, it's all in the browser

Day to day

./manage.sh status

./uninstall.sh

05 · Security

Only for the people you let in

Accounts

Everything needs a login. Admins start and stop modules, block devices, delete shared data and manage the accounts; users do everything else.

Mind the network

outpost speaks plain HTTP on your local network. Put a password on the hotspot, and use it where you trust who is around.

Your data stays

Nothing is sent anywhere. Uninstalling keeps your data unless you confirm deleting it, folder by folder.
